Build specification · companion to the motion proposal

How to actually land it

Each point of the overhaul, taken down to the level a developer can start on Monday: the change, the code, the edge cases that will bite, and the test that proves it shipped.

Baseline v8.4.3Tailwind v4 · @theme inline TanStack Router 1.170.18No new dependencies

Two constraints that shape everything below

No animation library. The installed router already supports viewTransition on <Link>, and Tailwind v4's @theme inline block already holds --ease-out and --ease-spring. Every effect specified here is CSS plus about forty lines of tokens. Adding Framer Motion would add 40KB to fix a problem that is architectural.

Every step ships alone. No item below depends on a later one. If the work stops after week two, what shipped is still coherent — which is the only honest way to plan a redesign around a one-person team.

01

Three planes, enforced by the router

3 days

A plane is not a style — it is a property of the destination. Declare it once per route and let the shell read it, so no screen can accidentally animate two ways.

Implementation

Put the plane in route context, where it travels with the route rather than the component:

// src/routes/_authenticated/trips.$tripId.tsx
export const Route = createFileRoute("/_authenticated/trips/$tripId")({
  staticData: { plane: "detail" },
  component: TripPage,
});

The shell reads it and stamps the frame. One attribute drives every transition rule:

// AppShell.tsx
const plane = useRouterState({
  select: (s) => s.matches.at(-1)?.staticData?.plane ?? "tab",
});
// …
<div data-plane={plane}>{children}</div>

The rule to write down

  • tab — cross-fade, 6px drift in the direction of travel. Never pushes.
  • detail — grows from origin, back shrinks to origin. Always has a back affordance.
  • sheet — rises over a scrim, dismissible by scrim tap, Escape and swipe-down. Never navigates onward.

Audit every current surface against this once. The trip to-do list is a sheet while trip stops are inline, at identical importance — pick one and apply it.

Will bite you

Sheets that contain navigation. Béa's planner sheet currently opens other surfaces from inside itself. A sheet that navigates has no coherent back behaviour — the browser back button will dismiss the sheet and the page underneath. Either the planner becomes a detail route, or its inner links become in-sheet steps.

Done when

  • Every route declares exactly one plane; a missing plane defaults to tab and logs in dev.
  • Browser back reverses the entering animation on all three planes.
  • No surface appears on two planes in different contexts.

02

Motion tokens, and removing the other seventeen

2 days

The theme block already holds the two curves. Add the durations beside them so motion is configured in the same place as colour, then sweep the ad-hoc values.

Tokens

/* styles.css — inside the existing @theme inline block */
--ease-standard: cubic-bezier(0.32, 0.72, 0, 1);  /* rename of --ease-out */
--ease-exit:     cubic-bezier(0.4, 0, 1, 1);
--ease-confirm:  cubic-bezier(0.34, 1.4, 0.5, 1); /* was --ease-spring */

--t-tap:    120ms;
--t-shift:  200ms;
--t-move:   320ms;
--t-arrive: 420ms;

Tailwind v4 exposes these automatically as duration-(--t-move) and ease-(--ease-standard), so component code reads as intent rather than numbers.

Sweeping the existing values

Seventeen duration-* declarations exist today. Map them by role, not by nearest number — a 300ms colour fade was wrong before and should become --t-tap, not --t-move: 

# find every one, with context, before changing any
grep -rn "duration-\[\?[0-9]" src/ --include=*.tsx

The global rule

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 1ms !important;
    transition-duration: 1ms !important;
    scroll-behavior: auto !important;
  }
}

Write this once, globally, rather than per component. Four scattered reduced-motion checks exist today; this replaces all of them and covers everything added later.

Will bite you

!important in that block will also flatten any transition someone later relies on for function — a height animation that reveals content, say. That is correct behaviour, but test the disclosure components under reduced motion before shipping, since a 1ms height transition must still end at the right height.

Done when

  • Zero arbitrary duration values remain in src/.
  • A lint rule rejects duration-[…] and raw cubic-bezier( outside the theme file.
  • Toggling reduced motion in OS settings visibly stills the app with no broken layout.

03

The sliding tab indicator

1 day

A single element that moves, rather than a class that jumps between five. With equal-width tabs this is one transform and no measurement.

Implementation

// AppShell.tsx — tabs are a 5-column grid, so index → percentage
const index = tabs.findIndex((t) =>
  t.to === "/" ? pathname === "/" : pathname.startsWith(t.to)
);

<nav className="relative grid grid-cols-5">
  <span
    aria-hidden
    className="absolute inset-y-0 left-0 w-1/5 rounded-2xl bg-primary-soft
               transition-transform duration-(--t-move) ease-(--ease-standard)"
    style={{ transform: `translateX(${Math.max(index, 0) * 100}%)` }}
  />
  {/* buttons sit above it with z-index */}
</nav>

Detail that separates good from adequate

  • Icon stroke thickens 1.7 → 2.3 over --t-shift, so activation survives a glance without relying on hue.
  • Label colour crossfades over --t-tap, faster than the indicator, so the destination reads as arriving before the pill lands.
  • Keep aria-current="page" on the link; the indicator is decorative and must be aria-hidden.

Will bite you

Index -1 on the fifteen routes with no tab. Clamping to 0 parks the pill under Home, implying you are on Home when you are on Settings. Better: hide the indicator entirely when index === -1 by fading it out — which also gives you a free signal that a route has no home in the navigation, the exact problem item 05 fixes.

Done when

  • The pill slides on every tab change and never jumps.
  • Screen readers announce only the tab, never the indicator.
  • On a route with no tab, no tab appears active.

04

Card to page, with the photo carrying across

1 week

The highest-value item on the list, and the one with the most edge cases. Two halves: make trips a route, then let the browser tween the shared photo.

Half one — the route

Retire the accordion. The expanded block in trips.tsx moves wholesale into trips.$tripId.tsx; the list keeps only the card. This also deletes the sessionStorage workaround that exists solely to stop the accordion collapsing on tab change — a real sign the route was always the right model.

Half two — the shared element

// The card and the page name the same element.
// The name must be unique per document, so key it by trip id.
<img style={{ viewTransitionName: `trip-photo-${trip.id}` }} … />

// The link opts in — router 1.170 supports this directly.
<Link to="/trips/$tripId" params={{ tripId: trip.id }} viewTransition>
/* styles.css — the browser tweens position and size for free; */
/* you only choose the timing. */
::view-transition-group(*) {
  animation-duration: var(--t-arrive);
  animation-timing-function: var(--ease-standard);
}

The stagger

Sections arrive 45–60ms apart, not together. Three or four steps maximum — beyond that it reads as slow rather than considered: 

.section-stagger > * { animation: rise var(--t-move) var(--ease-standard) both; }
.section-stagger > *:nth-child(2) { animation-delay: 45ms; }
.section-stagger > *:nth-child(3) { animation-delay: 90ms; }
.section-stagger > *:nth-child(n+4) { animation-delay: 135ms; }

Will bite you — four things

Duplicate names. Two cards with the same view-transition-name in one document silently disables the transition. Key by id, never by kind.

Safari support. Same-document view transitions have uneven support. The API degrades to a hard cut on its own, so no fallback code is needed — but test on a real iPhone and accept that some users get the old behaviour.

Scroll restoration. Returning to the list must land on the card you left, not the top. TanStack restores scroll by default; verify it survives the transition, since the snapshot is taken at navigation time.

Photos that have not loaded. A signed URL that is still fetching has no intrinsic size, so the tween starts from zero and the photo appears to explode. Hold the space with the fallback tint and only assign the transition name once the image has decoded.

Done when

  • Opening a trip grows from the tapped card; back shrinks into it.
  • The list returns to the previous scroll position.
  • With reduced motion on, it is an instant cut with correct layout.
  • A trip with no photo transitions as smoothly as one with.
  • sessionStorage trip-memory code is deleted.

05

Five tabs: folding Near into Places

1 week

The riskiest item, because it moves a destination people have learned. Do it as a merge with a redirect, not a deletion.

Sequence

  • Rename first, separately. Recs becomes Places in its own release. One change, easy to reason about, easy to revert.
  • Add the filter. A Near me chip beside the existing place filters, using the same location code Near already owns.
  • Move the distinctive parts. Near is not only a filter — it has pace-picking and "Arrange with Béa". Those become actions within the filtered view, not a separate screen.
  • Redirect, do not delete. /opportunities redirects to /recommendations?near=1 permanently. Old links, bookmarks and the guide steps keep working.

What the URL must carry

// Filter state belongs in the URL, not component state.
// Otherwise the redirect above cannot land anywhere meaningful.
validateSearch: (s) => ({
  near: s.near === "1" ? "1" : undefined,
  place: typeof s.place === "string" ? s.place : undefined,
  kind: typeof s.kind === "string" ? s.kind : undefined,
}),

Will bite you

Near is the product's best argument and it is about to lose its front door. "Past You left a breadcrumb" is the moment that justifies the whole app, and a filter chip is a quieter home than a tab. Compensate deliberately: the proximity nudge should surface on Home and inside a trip, where it is arguably more useful than in a tab nobody opens while walking. If that compensation does not ship in the same release, keep six tabs.

Done when

  • Five tabs; every one of the 21 routes has a parent tab.
  • /opportunities redirects and the guide steps still resolve.
  • Filter state round-trips through the URL and survives a share.
  • A proximity nudge appears on Home.

06

Four primitives, applied everywhere

2 weeks

Cohesion is enforced by making the consistent path the easy path. Each primitive should be less work to use than to avoid.

PageHeader

<PageHeader
  eyebrow="14 saved"
  title="Recommendation vault."
  action={<Button>Share</Button>}   // optional, max one
  compress                          // scroll-linked, default on
/>

Compression is the highest-value shared behaviour: at 48px of scroll the serif title shrinks to a 44px bar. Drive it with a scroll listener on the shell's single scroll container — the app has exactly one, which makes this cheap.

Section — already built, needs promoting

TripSection exists and works. Move it to components/Section.tsx, drop the trip-specific naming, and use it on every tab. This alone removes most visual drift between screens.

Card anatomy

<ContentCard
  media={<Banner … />}      // optional, always first
  title="Japan, September"
  meta={["Kyoto & Sapporo · 12 days", "Sep 17 – 28"]}  // max 2 lines
  badge="in 2 months"
  actions={<IconRow … />}   // optional, always last
/>

Trips, saved places, cities and memories all use it. Different content, identical skeleton.

Tab identity

/* One hue rotation of the accent, two usages only. */
[data-tab="trips"]  { --tab-accent: oklch(0.535 0.162 39); }  /* terracotta */
[data-tab="places"] { --tab-accent: oklch(0.535 0.150 55); }
[data-tab="world"]  { --tab-accent: oklch(0.535 0.140 22); }

Used in the header rule and the active pill. Nowhere else. Lightness and chroma stay fixed so every tab has identical contrast — this is why the palette is in oklch, and it is the payoff for that choice.

Will bite you

Primitives added without deleting what they replace. Béa already has five surface treatments because each new one was added alongside the last. Every primitive lands with a migration commit that converts existing call sites, or it becomes the sixth option.

Done when

  • No screen starts with anything but PageHeader.
  • Raw bg-card / bg-elevated fail lint outside the primitives.
  • Header compression behaves identically on all five tabs.

07

The details people cannot name

1 week

Optimistic writes

Partly present. Make it the rule and make failure visible: apply locally, reconcile on response, and on error revert with a toast naming what failed — never a silent snap-back, which reads as the app being broken. 

// The existing toggle already does this well — generalise the shape.
setRows((cur) => cur.map(apply));        // 1. local, instant
const { error } = await write();          // 2. network
if (error) { await reload(); toast.error(…); }  // 3. revert loudly

Skeletons shaped like the content

One skeleton per card type, matching its real dimensions, so nothing reflows on arrival. Fifteen skeleton references exist against 28 loading flags — the gap is where the layout jumps today.

Haptics, honestly scoped

export const tap = () => {
  if (matchMedia("(prefers-reduced-motion: reduce)").matches) return;
  navigator.vibrate?.(8);  // Android only; iOS Safari has no API
};

Use on save and undo. Because iOS cannot receive it, haptics must never be the only feedback for anything — treat it as a bonus on the platforms that support it.

Done when

  • No write blocks the interface; every failure surfaces a message.
  • No layout shift between skeleton and content (CLS under 0.1).
  • Every list with a loading state has a matching skeleton.

08

Proving it worked

2 days

A redesign with no measurement is an opinion. None of this is measurable today, because the app collects nothing — so instrumentation is the first item, not the last.

Instrument before you start

  • INP — interaction to next paint, per route. Transitions must not push it above 200ms; if they do, the animation is running on the main thread and needs to be transform-only.
  • CLS — cumulative layout shift. Skeletons should drive it down; a rise means they are the wrong shape.
  • Guide step triggers — which of the 55 steps people actually open. This turns the tour into the design backlog rather than a guess about which screens confuse people.
  • Trip open → first edit — the clearest proxy for whether the detail page reads as a place you can act, rather than a page you read.

The honest test

Five people, twenty minutes each, before and after. Nothing in this document substitutes for watching someone fail to find the thing. It is also the cheapest research available and the only one that can tell you the five tabs were right.

Done when

  • INP and CLS reported per route, with a before/after baseline captured this week.
  • Guide-step opens tracked, reviewed monthly, feeding the redesign backlog.
  • One round of five-person testing completed before the tab merge ships.
